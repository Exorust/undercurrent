# F11 — `GET /topics`: growth, CS correction, arriving sub-topics

Walk with: `curl` and one DuckDB cross-check.

## Flow F11.1 — default window, topic level
Preconditions: server running on a database where the last complete month is M (October 2026 on 2026-11-06).
| step | action | expected result (observable) |
|---|---|---|
| 1 | `GET /topics` (no params) | `window.to` = M, `window.from` = M−5, `prior_from` = M−11, `prior_to` = M−6, `last_complete` = M; `vol_ratio` equals `vol_recent / vol_prior` (×1.36 on 2026-11-06 data) |
| 2 | `topics` length | 116 |
| 3 | pick a topic; recompute `((recent+1)/(prior+1)) / vol_ratio` | equals `growth` ± 1e-6 |
| 4 | cross-check `recent` for that topic with `select sum(n) from topic_months where level=1 and cluster=c and month between from and to` | equal |
| 5 | a topic with `is_new: true` | has `recent >= 30` and `prior < 5` and `growth` null |
| 6 | `arriving` of a topic | each entry is a level-0 cluster whose `topic_parent.parent` is this topic, with `recent >= 30` and `window_share >= 1.6 * corpus_share`, where `window_share` = its papers in `[from, to]` / its papers in all complete months and `corpus_share` = the same ratio over all papers; the entry carries `window_share`, `corpus_share` and `onset` (PM correction 2026-11-07, user decision: arriving = window-share rule) |
| 7 | count of all arriving entries across topics | > 0 on the 2026-11 data (about 14 at 6 months measured 2026-11-06); the list is pasted into STATUS; the robot world-model cluster (`action, manipulation, robot, world`) and at least one LLM-agent cluster are present (PM correction 2026-11-07, user decision: arriving = window-share rule) |
