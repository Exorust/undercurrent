# F16 — Ideas between A and B with the citation check

Walk with: `curl` (one real `claude -p` call per flow; each costs 10–40 s of subscription quota) and DuckDB on `data/workbench.duckdb`.

## Flow F16.1 — a successful ideas call
Preconditions: `sel_a`, `sel_b` transient selections (F13.1) of two linked topics; no other ideas call running.
| step | action | expected result (observable) |
|---|---|---|
| 1 | `POST /ideas -d '{"a":"<a>","b":"<b>","n":3}'` | `200` within 120 s; `shown` has ≤ 28 entries, each `paper` + `side` in `A / B / bridge`; at most 8 `bridge`, ≤ 10 per side |
| 2 | `ideas` | 1 to 3 entries `{idea_id, title, text, cited, status: "ok"}`; every id in `cited` is in `shown`; each idea cites (≥ 1 A and ≥ 1 B) or ≥ 1 bridge |
| 3 | `GET /selections` | both `a` and `b` now appear as saved (auto-saved, unnamed → name like `Topic: <label>`) |
| 4 | `select count(*) from ideas where status='ok'` on `data/workbench.duckdb` | equals the number returned; row stores `a_sel, b_sel, shown_ids, model, window_from, window_to, created` |
| 5 | restart the server; `GET /ideas?a=<a>&b=<b>` | the same ideas are returned |
| 6 | `dropped` | integer ≥ 0, plus `dropped_reasons` (list of strings, one per dropped idea, each naming the offending `arXiv:` id when there is one); if > 0, `select reason from ideas where status='dropped'` shows the same reason text (PM correction 2026-11-06: the page needs the reasons for F29.4–5) |

## Flow F16.2 — concurrency and validation
Preconditions: server running.
| step | action | expected result (observable) |
|---|---|---|
| 1 | start one `POST /ideas`, and within 1 s send another | the second returns `409`, `error: "ideas_busy"` immediately; the first completes normally |
| 2 | `POST /ideas -d '{"a":"<a>","b":"<a>"}'` | `400` (A and B must differ) |
| 3 | `POST /ideas -d '{"a":"<a>","b":"<b>","n":9}'` | `400` (n in 1..5) |
| 4 | `POST /ideas` with an unknown `sel_id` | `404` |

## Flow F16.3 — citation check and regeneration (fault injection)
Preconditions: server started with `RADAR_LLM_FAKE=<path>` pointing to a script that returns canned text (test hook), or `radar.llm.ask` monkey-patched via a `--fake-llm` flag.
| step | action | expected result (observable) |
|---|---|---|
| 1 | fake returns one idea citing `arXiv:2405.01234` (not in the shown set) twice in a row | response `ideas: []`, `dropped: 1`; `ideas` table has one row `status='dropped'`, `reason` contains `2405.01234`; stderr logged the drop |
| 2 | fake returns an idea citing nothing | dropped with reason `cites no paper` |
| 3 | fake returns an idea citing only A-side papers (no B, no bridge) | dropped with reason mentioning `both sides` |
| 4 | fake returns invalid JSON, then valid on retry | `200`, ideas present; log shows `parse failed, retrying whole call` once |
| 5 | fake returns invalid JSON twice | `502`, `error: "llm_failed"`; nothing stored |
| 6 | fake exits non-zero | `502`; nothing stored |
| 7 | fake sleeps beyond timeout (`--llm-timeout 2` for the test) | `504`, `error: "llm_timeout"` |
