# F3 — kNN precision gate

Walk with: `.venv/bin/python -m radar.links --check-knn` (or the flag the build chooses; must be documented in the module docstring).

## Flow F3.1 — 1,000-paper check against exact search
Preconditions: F2 passed; `embeddings` table present.
| step | action | expected result (observable) |
|---|---|---|
| 1 | run the check | stdout has one line of the form `knn check: 1000 papers, bridge decision agrees 97.3% (gate 95%), recall@14 0.91` with real numbers; exit code 0 when agreement ≥ 95% |
| 2 | `select knn_recall14, knn_bridge_agree from map_meta order by created desc limit 1` | both non-null; `knn_bridge_agree` equals the printed value |
| 3 | run the check a second time with a different seed (`--seed 7`) | agreement within 2 percentage points of the first run |

## Flow F3.2 — error path: gate fails
Preconditions: a deliberately degraded graph (for example `--n-neighbors 5` on the dev database) or a mocked threshold `--gate 99.9`.
| step | action | expected result (observable) |
|---|---|---|
| 1 | run the check with `--gate 99.9` | stdout states `FAIL: bridge decision agrees 97.3% < gate 99.9%`; exit code 1; `map_meta` still updated with the measured value |
| 2 | start the server (F8) after a failed gate | server starts but `GET /meta` carries `knn_bridge_agree` and the page shows the measured value in the (i) popover (F20); it does not refuse to start |
