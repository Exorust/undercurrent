## Merge ideas

### Robot Manipulation Learning
*cosine distance from home field 0.06, topic growth x1.8*

Vision-language-action (VLA) policies such as OpenVLA (arXiv:2406.09246) are hard to run at control rate on a laptop-class device, and this is a kernel and small-model problem. OpenVLA decodes 7 billion parameters one action token at a time, which is too slow for closed-loop manipulation on local hardware. The idea is to put a small VLA on Apple Silicon with custom Metal kernels. The model would use the π0 design (arXiv:2410.24164), a small pretrained vision-language backbone plus a separate flow-matching "action expert" that outputs a chunk of actions in a few denoising steps. The fit is plausible for two reasons. The action expert is a small transformer that runs the same few steps many times, so fusing those steps into one Metal kernel should remove most launch and memory overhead. Unified memory also avoids copying camera frames between CPU and GPU. The first experiment is to take Octo (arXiv:2405.12213), which is small enough to run without heavy changes, and port its diffusion action head to MLX with a hand-written fused Metal kernel for the denoising loop. I would compare latency per action chunk and task success in simulation against the stock PyTorch MPS version, then repeat with 4-bit quantization of the backbone to see where success rate starts to drop. If the fused kernel does not beat the baseline by a clear margin, I would stop and not scale up to the larger models.

### Speech and Audio Generation
*cosine distance from home field 0.06, topic growth x1.5*

Idea: use the flow-matching sampler from F5-TTS (arXiv:2410.06885) to generate several output tokens in parallel in an on-device small language model, instead of decoding strictly one token at a time. The home-field problem is that decoding on Apple Silicon is limited by memory bandwidth, so a small coding agent spends most of its time on sequential single-token steps. F5-TTS is fully non-autoregressive and uses Sway Sampling to get good quality from few inference steps, which suggests a short block of tokens could be refined together in a handful of steps. The fit is plausible because Moshi (arXiv:2410.00037) shows that a small, real-time model can hold latency to a few hundred milliseconds on the output side, so a latency budget for interactive use is already a known target. The fit is uncertain because text tokens are discrete and speech frames are continuous, so the method would need to run on token embeddings, or the model would need a separate step that maps the result back to tokens. The first experiment is to take a 1B-parameter model, fine-tune a small head that denoises blocks of 4 to 8 draft tokens in embedding space with flow matching, and measure tokens per second and acceptance rate against ordinary decoding on a Metal kernel-writing benchmark. If it fails to beat speculative decoding, drop it. A second check is whether the same treatment helps on audio inputs as in Qwen2-Audio (arXiv:2407.10759), but only after the text case works.

### Game Theory and Auctions
*cosine distance from home field 0.07, topic growth x1.5*

The method is learning-augmented ski rental from arXiv:2407.17712, applied to memory management in an on-device coding agent. A coding agent harness running a small language model on Apple Silicon has to decide, for each idle session, whether to keep its KV cache (the stored attention state) in unified memory or evict it. Keeping it costs memory every second, and evicting it costs a full prefill (re-processing the whole prompt) on the next turn. That is a ski-rental problem: you don't know how long the user will stay idle, so you pay "rent" until the total reaches the cost of "buying" the cheaper option. The paper's method adds a predictor, such as a small model of when the user will return, and its guarantee holds up even when the predictor is wrong. A third option fits the same framework: compress the idle cache with an error-bounded lossy compressor from the families surveyed in arXiv:2404.02840, which costs less than a prefill but loses some accuracy. When several agents or apps share the same GPU and memory, arXiv:2603.09902 suggests checking whether each one's greedy eviction choice leaves everyone worse off than a shared policy would. The first experiment is to replay real harness traces (idle gaps and prefill costs) from a Metal-based runtime and compare three policies: always keep, fixed-timeout evict, and prediction-guided ski rental. The measures would be total memory-seconds, added latency, and the share of turns that need a re-prefill.

### Video Action Recognition
*cosine distance from home field 0.06, topic growth x1.4*

Video action recognition has a technique that could help with the long, noisy context problem in coding agents: VideoMamba's linear-time state space model (arXiv:2403.06977), which handles very long frame sequences without the quadratic cost of attention. An agent harness running a small on-device model on Apple Silicon has a similar problem. The tool-call and edit history grows past what a small model can attend to cheaply, and memory is limited. The fit is plausible because an agent trajectory resembles a video: a long ordered stream of states with mostly small changes between steps, where the model must track what changed and recognize the current activity. V-JEPA (arXiv:2404.08471) points to a training signal that suits this, since it predicts features of the next segment instead of reconstructing raw input, which would let a small model learn compact trajectory summaries without generating text. Ego-Exo4D (arXiv:2311.18259) is relevant because it separates fine-grained activity understanding from proficiency estimation, and that maps to telling apart what a coding agent is doing from whether it is making progress or looping. The first experiment is to log several hundred agent trajectories from a coding-agent harness and encode each step as a feature vector. Then train a small Mamba-style model to predict the next step's features, and test whether its prediction error flags stuck or looping runs earlier than a fixed-window attention baseline of the same size. Compare the two on detection lead time and on memory use on an M-series Mac.

### Matrix Computations and Inverse Problems
*cosine distance from home field 0.07, topic growth x1.4*

Use a sparse linear solver as the template for a verifier-guided kernel search: take the LLM-guided equation discovery loop from arXiv:2404.18400, where a model proposes programs and a numerical fit scores them, and apply it to GPU kernels for a small on-device model on Apple Silicon. The problem is that hand-writing Metal kernels for matrix operations (for example, low-rank or structured-sparse weight layouts) is slow, and the best tile and layout choices depend on the specific chip. The fit is plausible because both settings ask a model to write short programs that a cheap, exact scorer can check, and arXiv:2409.09359 shows that keeping a library of reusable learned concepts beats unguided search. The same idea could store reusable kernel fragments, such as tiling patterns and threadgroup memory layouts. Photonic tensor cores like the one in arXiv:2311.16896 are a useful reminder that matrix-multiply hardware is changing quickly, so a search method that re-learns kernels per target hardware may age better than hand tuning. The first experiment is to pick one operation, a quantized matrix-vector product from a 1B-parameter model, and let a coding agent generate Metal kernel variants. Each variant is checked for correctness against a reference and timed on one M-series chip, and a concept library of winning fragments is carried between rounds. Compare the best kernel after a fixed budget of 200 candidates, with and without the library, against the existing MLX kernel.

### GPU and Cloud Energy Efficiency
*cosine distance from home field 0.05, topic growth x1.3*

Energy-aware kernel search: take the multi-objective container-allocation approach from arXiv:2401.12698 (NSGA-II, a genetic algorithm that returns a Pareto front instead of a single best answer) and apply it to the search loop that LLM-driven GPU kernel generators use. Today, benchmarks like arXiv:2502.10517 (KernelBench) rank generated kernels by correctness and speedup (fast_p), so a kernel that is 1.3x faster but draws far more power looks better than a slower, cooler one. That matters most on Apple Silicon and on-device setups, where the thermal and battery limit is often tighter than the latency limit. The fit is plausible because kernel variants differ in measurable ways (tile size, threadgroup size, memory layout), and these trade latency against energy in a way a Pareto search handles well. The "Edge AI" review, arXiv:2407.04053, names resource constraints as a main open problem for edge systems, which is the same constraint here. First experiment: take 20 to 30 KernelBench tasks, have a coding agent generate 8 Metal kernel variants for each, and measure latency and energy per call (for example with `powermetrics`). Then compare the Pareto front of those variants against the one you get by picking only the fastest, and check how often the fastest kernel is not on the energy-aware front.

### Physics-Informed Neural Operators
*cosine distance from home field 0.08, topic growth x1.2*

Physics-informed neural operators learn a mapping from input functions to PDE solutions, and Transolver (arXiv:2402.02366) does this by grouping mesh points in similar physical states into a small number of learnable "slices" and running attention only over those slices. The home-field problem is long-context attention cost for small on-device language models on Apple Silicon. Memory traffic dominates at long context, and a coding agent harness that keeps a large repo or tool-output history in context hits that limit quickly. The fit is plausible because Transolver's slice step is a learned soft clustering of tokens into a fixed number of groups, which makes attention cost linear in sequence length, and token sequences in agent traces are highly repetitive, much as mesh points in smooth regions of a PDE domain are. Poseidon (arXiv:2405.19101) shows that this kind of multiscale operator transformer can be pretrained once and then adapted to new tasks, which suggests a slice-attention layer could be swapped into a pretrained small model and fine-tuned briefly. The first experiment is to replace the attention in a 0.5B to 1B parameter model with a Physics-Attention-style slice layer (64 slices), fine-tune it on coding-agent transcripts, and compare perplexity and tokens per second at 32k context against the original model on one M-series Mac. The kernel work follows from this, since the slice and deslice steps are two dense matmuls with a softmax and could be written as one fused Metal kernel. The comparison to run alongside is a KAN-based variant (arXiv:2406.02917 benchmarks KANs against MLPs for operator learning), to check whether a KAN replacement of the feed-forward block gives any accuracy gain per parameter at small model sizes.

### Medical Image Analysis
*cosine distance from home field 0.08, topic growth x1.1*

Idea: use the selective state space model (Mamba) scan from medical segmentation as the sequence mixer in an on-device small language model for a coding agent harness, with a custom Metal kernel for the scan. Agent harnesses re-feed long tool outputs, logs and file contents on every turn, and on Apple Silicon the attention KV cache for those contexts eats limited unified memory and bandwidth. The medical imaging work shows the scan handles long sequences with linear cost: arXiv:2401.13560 (SegMamba) keeps processing speed high over whole 3D volumes, and arXiv:2401.04722 (U-Mamba) adopts it specifically for long-range dependencies. The fit is plausible but not guaranteed. arXiv:2404.09556 (nnU-Net Revisited) found that well-tuned CNN U-Nets still beat Mamba-based models, so the claimed gains may come from weak baselines, and the same caution applies to language modeling. First experiment: write a Metal selective-scan kernel, benchmark it against the attention path at 8k to 64k tokens of recorded agent traces on an M-series Mac for tokens per second and peak memory, and then check whether a small hybrid model (a few Mamba layers mixed with attention) keeps accuracy on tool-output retrieval tasks against a tuned attention-only baseline of the same size.
